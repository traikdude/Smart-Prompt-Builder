# Smart-Prompt-Builder v2.15.1 Release Notes

**Release Date:** April 14, 2026  
**Phase:** 7.5 — Vertex AI Tuning Submission Pipeline  
**Codename:** Closing the Loop

---

## Overview

v2.15.0 wired the `Corrections` tab and the JSONL exporter that converts it into Vertex AI supervised-tuning format. v2.15.1 closes the remaining gap: a **submission script** that takes that JSONL the rest of the way — uploading it to GCS and kicking off a Vertex AI SFT job against a tunable Gemini base model — plus a **one-shot wrapper** that chains export → upload → submit in a single command.

After this patch, the full pipeline runs end-to-end:

```
Corrections tab → export_corrections_vertex.py → JSONL
              → submit_vertex_tuning_job.py → GCS upload + Vertex SFT job
              → tuned Gemini model
```

---

## What Changed

### Added — `backend/scripts/submit_vertex_tuning_job.py`
- **Accepts local JSONL or `gs://` URI** via `--dataset`. Local files are uploaded to `gs://<bucket>/tuning-datasets/<UTC-timestamp>/<basename>` before submission.
- **Calls `vertexai.tuning.sft.train`** with `source_model`, `train_dataset`, and `tuned_model_display_name` (auto-timestamped if `--tuned-name` not provided).
- **Optional hyperparameter overrides:** `--epochs`, `--learning-rate-multiplier`, `--adapter-size`. Omit to let Vertex pick defaults.
- **Lazy SDK imports** — `google-cloud-aiplatform` and `google-cloud-storage` are imported inside the functions that need them, so dry-runs and `--help` work without the SDKs installed and the Cloud Run image stays slim.
- **`--dry-run` is upload-free** — when the dataset is local, dry-run prints the would-be GCS path without touching the network or requiring `google-cloud-storage`.
- **UTF-8 stdout** — `sys.stdout.reconfigure(encoding="utf-8")` so dry-run prints survive Windows `cp1252` consoles.

### Added — `backend/scripts/tune_from_corrections.py`
- **One-shot wrapper** chaining `export_corrections_vertex.py` → `submit_vertex_tuning_job.py`.
- **Validates required env** (`GOOGLE_SERVICE_ACCOUNT_JSON`, `RLHF_SHEET_ID`) before running anything.
- **Intermediate JSONL** written to `--workdir` (defaults to system temp) with a UTC-timestamped filename, then deleted on success unless `--keep` is passed.
- **Empty-dataset guard** — if the Corrections tab has no rows yet, the wrapper exits cleanly without invoking the submit step.
- **Argument passthrough** — any flag not consumed by the wrapper is forwarded to the submit step, so `--base-model`, `--epochs`, etc. still work end-to-end.
- **`--dry-run`** is forwarded to the submit step so the entire pipeline can be exercised without a real GCS upload or Vertex job.

### Not Bumped (intentionally)
- `APP_VERSION` in `backend/main.py` and `version` in `package.json` remain at `2.15.0`. v2.15.1 is purely additive tooling — it ships two CLI scripts and a release note, and changes no runtime code. The git tag alone marks the patch; bumping the runtime constants would force a frontend rebuild + clasp push for no telemetry benefit.

## Pipeline Reference

```bash
# One-time SDK install (kept out of backend/requirements.txt — these are CLI-only deps)
pip install google-cloud-aiplatform google-cloud-storage

# Required env
export GOOGLE_SERVICE_ACCOUNT_JSON="$(gcloud secrets versions access latest \
    --secret=GOOGLE_SERVICE_ACCOUNT_JSON --project mortalzwardrobe)"
export RLHF_SHEET_ID=1_3BzdeAqqHryrlVu9iQNNYc4P2fxFAjQNg5SXI3CfpM

# Full chain (dry-run — exports for real, submit step previews only)
python backend/scripts/tune_from_corrections.py \
    --bucket spb-tuning-datasets \
    --dry-run

# Real submission
python backend/scripts/tune_from_corrections.py \
    --bucket spb-tuning-datasets \
    --base-model gemini-2.5-flash-002
```

## Known Gaps (deferred, not bugs)

- **Validation split** — Not produced. Meaningless until the dataset grows.
- **Job polling / status** — Not implemented. Tuning jobs run for hours; check via `gcloud ai custom-jobs list` or the Vertex console using the resource name printed at submission time.
- **Tunable model ID** — `gemini-2.5-flash-002` is the current default. Vertex tunable IDs change over time; verify against `gcloud ai models list --region=us-central1` before each real run and override with `--base-model`.
- **`backend/scripts/export_tuning_dataset.py`** still reads only the first sheet tab and is therefore blind to the `Corrections` tab. The Vertex pipeline (this script) is unaffected; the legacy AI Studio path will need a similar tab-aware update when next touched.
