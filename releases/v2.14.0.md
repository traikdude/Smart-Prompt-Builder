# Smart-Prompt-Builder v2.14.0 Release Notes

**Release Date:** April 13, 2026  
**Phase:** 7.4 — Ideal-Output Capture on Downvotes  
**Codename:** Correction Loop

---

## Overview

Phase 7.4 completes the highest-leverage ML enhancement in the RLHF roadmap: **negative feedback with human-supplied corrections**. A single downvote with an ideal output correction is worth approximately 10 thumbs-up signals for model tuning.

When a user clicks 👎 on any output payload, an expandable correction textarea now slides in, letting them paste the output they *expected*. This correction flows through the entire pipeline — from frontend → backend → Google Sheets → JSONL exporter — as a high-quality negative training example.

---

## What Changed

### Backend (`main.py`) — Pylint 10.00/10
- **`FeedbackRequest.ideal_output`** — New optional field (`Optional[str]`, default `None`).
- **Sheet schema extended** — Writes 7 columns now (A-G): `[timestamp, rating, prompt, lens, model, output, ideal_output]`. Backwards-compatible with existing 6-column rows.
- **`refresh_rlhf_cache`** — Range updated from `A:F` to `A:G` for forward-compatibility.
- **Version** — Bumped to `2.14.0`.

### Exporter (`export_tuning_dataset.py`) — Pylint 10.00/10
- **Dual training paths:**
  - **Path A (Positive):** `rating=1` → `{text_input, output}` from actual AI output.
  - **Path B (Correction):** `rating=0` + non-empty `ideal_output` → `{text_input, output: ideal_output}`.
- **CLI flags:**
  - `--dry-run` — Prints records to stdout instead of writing to file.
  - `--limit N` — Caps the number of records exported.
  - `--output FILE` — Custom output file path.
- **`build_column_index`** — `ideal_output` mapped as an *optional* column (never required).
- **Unified stats** — Tracks `positive`, `correction`, `short`, `dupes`, `skipped`.

### Frontend (`MultiOutputCard.tsx` + `App.tsx`)
- **Correction textarea** — After 👎, an amber-bordered textarea slides in with `Skip` / `Submit Correction` buttons.
- **`handleFeedbackSubmit`** — Now accepts optional `idealOutput` string and includes it in the POST body.
- **Contextual toasts:**
  - 👍 → `Rated helpful! 🙌`
  - 👎 with correction → `Correction submitted — thank you for improving the model! 🎯`
  - 👎 without correction → `Got it — we'll keep improving! 🛠️`

## Data Flow

```
User clicks 👎 on output payload
  → Correction textarea slides in (amber border, "Ideal Output" label)
  → User pastes expected output
  → Clicks "📨 Submit Correction"
  → POST /api/v1/feedback { rating: 0, ..., ideal_output: "..." }
  → Backend writes to Sheet column G
  → Exporter (Path B) picks up: {text_input, output: ideal_output}
  → Ready for Vertex AI fine-tuning
```

## Sheet Schema (A-G)

| Column | Field | Required | Notes |
|--------|-------|----------|-------|
| A | timestamp | ✅ | ISO 8601 UTC |
| B | rating | ✅ | `1` = up, `0` = down |
| C | original_prompt | ✅ | User input text |
| D | selected_lens | ✅ | Active format lens |
| E | model_used | ✅ | Gemini model ID |
| F | payload_content | ✅ | Actual AI output |
| G | ideal_output | ❌ | Human correction (downvotes only) |

## Smoke-Test Commands

```bash
# Dry-run with 5 record limit (stdout only, no file write)
python backend/scripts/export_tuning_dataset.py --dry-run --limit 5

# Full export to custom file
python backend/scripts/export_tuning_dataset.py --output training_data.jsonl
```
